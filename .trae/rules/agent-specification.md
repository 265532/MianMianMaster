# Agent Coding 行为规约

## 核心原则

**遇到任何不明确的地方，必须主动提问，绝不猜测用户意图。**

## 具体要求

### 1. 需求不明确时
- 功能的边界条件不清晰 → 提问
- 技术选型有多种合理方案 → 提问并说明各方案利弊
- 发现需求可能存在逻辑漏洞 → 提问确认
- 用户的描述有多种理解方式 → 提问澄清

### 2. 实现细节不明确时
- 不确定现有代码的实现方式 → 先阅读代码，再提问
- 不确定某个配置的具体含义 → 提问
- 不确定是否需要处理某种边界情况 → 提问

### 3. 禁止行为
- ❌ 凭猜测选择"最可能"的理解
- ❌ 假设用户会接受默认选项
- ❌ 在多个合理方案中选择一个而不告知用户
- ❌ 用"通常情况下"、"一般来说是"来替代确认

## 示例

**不明确的输入**：
> "帮我优化这个查询"

**正确的做法**：
> "我需要确认几个问题：
> 1. 优化目标是什么？（速度 / 内存 / 可维护性）
> 2. 是否有具体的性能指标要求？
> 3. 当前查询存在什么问题？（响应慢 / 数据量大 / 其他）

---

*本规约优先级高于其他默认行为提示。*
